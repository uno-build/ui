title: TypeGPU World Space

`UITypeGPU` renders uno UI into a texture and draws it on a plane inside a scene rendered with TypeGPU and [TypeGPU Kit](https://docs.swmansion.com/typegpu-kit/). The plane can move, rotate, and scale while its UI remains interactive.

This section continues the [TypeGPU](./typegpu.mdx) guide. TypeGPU Kit has no scene graph: the plane is a drawing that you add to a pass description, with a matrix that places it. The pass decides the target format, the depth test, and the samples per pixel.

## Shared setup

Start from the TypeGPU [shared setup](./typegpu.mdx#shared-setup): a `createScene(root, surface)` function run by `web.host()`, with `resources` created on the surface's device and context. The code in this guide goes in `createScene`, the drawing in the scene's `frame(frame)`, and the cleanup in its `destroy`.

## 1. Create the UI plane

Replace the `UI` import and `UI.create()` call with `UITypeGPU`. Pass it the TypeGPU root as well as the shared resources. It returns the uno UI instance and a plane with its texture and material already connected:

```js
import UITypeGPU from '@uno.build/ui/UITypeGPU'

const UI_SIZE = 400
const device_pixel_ratio = surface.pixelRatio

const { ui, plane } = await UITypeGPU.create({
  root,
  resources,
  device_pixel_ratio,
  texture_width: Math.round(UI_SIZE * device_pixel_ratio),
  texture_height: Math.round(UI_SIZE * device_pixel_ratio),
  world_width: 2,
  world_height: 2,
})

ui.setViewport(UI_SIZE, UI_SIZE)
```

- `root`: The TypeGPU root that draws the scene. It must use the same device as `resources`.
- `texture_width`, `texture_height`: Sets the resolution of the UI texture in physical pixels.
- `world_width`, `world_height`: Sets the size of the plane in world units.
- `ui.setViewport(width, height)`: Sets the space available for the UI layout in logical pixels.

## 2. Set up the camera

```js
import * as cameras from '@typegpu/kit/cameras'

const view = cameras.orbit(root, { size: surface, target: [0, 0, 0], distance: 3 })
ui.setCamera(view)
```

With `ui.setCamera(view)`, uno casts a ray through `view.rayAt()` onto the plane and converts the hit position into UI layout coordinates. The component's existing pointer, click, and focus handlers work as the plane rotates. Orbit, flat, and custom cameras all work. The camera that draws the plane is the one piped into the pass description, below.

For pointer, click, and wheel events, the payload described in [Event data](../api/events.mdx#event-data) also includes `distance_to_camera` when the ray hits the plane. It is the distance from the ray's origin to the hit position in world units: from the eye of an orbit camera, and from the plane of a flat camera, where it is negative for hits in front of that plane. The `x` and `y` fields remain coordinates in the UI's logical coordinate space.

## 3. Add the plane to the scene

By default, `plane` is a rectangle of `world_width` by `world_height` in its local XY plane, facing `+Z` and visible from both sides. `plane.drawing` is a TypeGPU Kit drawing. Add it to the description of the pass that draws your scene:

```js
import * as finish from '@typegpu/kit/finish'
import * as passes from '@typegpu/kit/passes'
import * as targets from '@typegpu/kit/targets'

const scene_targets = targets.create(root, surface, {
  color: { format: 'rgba16float', sampled: true },
  depth: { format: 'depth24plus' },
})
const scene = passes
  .create(root, scene_targets, { color: passes.color, depth: passes.depth })
  .pipe(view.inject())
const final = finish.create(root, {
  format: surface.format,
  source: () => scene_targets.textures.color,
  tone: null,
  settings: { vignette: 0 },
})

const drawn = scene.add(plane.drawing)
```

In `frame(frame)`, draw the UI texture before the pass that shows it:

```js
import { mat4 } from 'wgpu-matrix'

view.update(frame.dt)
plane.setTransform(mat4.rotationY(Math.sin(frame.time / 2) * 0.8))

ui.update()
ui.draw({ submit: false, command_encoder: root.unwrap(frame.encoder) })

scene_targets.fit()
scene.record(frame, drawn)
final.record(frame, surface.view(frame))
```

- `plane.setTransform(matrix)` takes a column-major world matrix of 16 values, such as one from [wgpu-matrix](https://wgpu-matrix.org/), and places the plane for both drawing and picking. `plane.transform` holds the current matrix; writing to it directly does not move the drawing.
- `ui.draw()` updates the plane's texture rather than the canvas. `root.unwrap(frame.encoder)` gives it the frame's WebGPU encoder, so the frame is still submitted once.
- The drawing blends over what the pass already holds and tests the depth without writing it. Record it after the opaque drawings, and record planes that overlap on screen from the farthest to the nearest.

## Colors

The default material writes premultiplied linear colors, as a TypeGPU Kit scene is drawn in linear colors and its final pass maps them to the canvas. That pass applies its tone curve and vignette to the UI too. `tone: null` and `vignette: 0` leave the colors as they are, up to the dither of one 8-bit step that `dither: 0` removes; with a curve such as the default `tone.neutral`, bright UI colors shift.

For a pass that writes encoded colors straight to the canvas, create the material with `createTypeGPUMaterial(root, texture, 'srgb')`. For example, this draws the plane over the finished frame with a pass straight to the `surface`, as in the [shared setup](./typegpu.mdx#shared-setup), which keeps a tone curve for the scene and the exact colors for the UI:

```js
import UITypeGPU, { createTypeGPUMaterial } from '@uno.build/ui/UITypeGPU'

const { ui, plane } = await UITypeGPU.create({
  //...
  createMaterial: ({ texture }) => createTypeGPUMaterial(root, texture, 'srgb'),
})

const overlay = passes.create(root, surface).pipe(view.inject())
const drawn = overlay.add(plane.drawing)

// In the frame, after final.record()
overlay.record(frame, drawn, { clear: false })
```

A screen has color only, so this plane draws over the scene's objects rather than behind them.

## Customize the material

The material holds the bind group of the UI texture and `pixelOf`, the function that gives the plane its color at each pixel. To shade the plane differently, add the drawing with another `pixelOf`. It receives the vertex, with its `uv` and `world_position`, and returns a `Pixel` with a premultiplied `color`.

For example, this lights the UI with a TypeGPU Kit [lighting](https://docs.swmansion.com/typegpu-kit/kit/lighting/):

```js
import * as lighting from '@typegpu/kit/lighting'
import * as materials from '@typegpu/kit/materials'
import * as shading from '@typegpu/kit/shading'
import * as std from 'typegpu/std'

const light = lighting.create(root)
const scene = passes
  .create(root, scene_targets, { color: passes.color, depth: passes.depth })
  .pipe(view.inject())
  .beneath(light.inject())

const { ui, plane, material } = await UITypeGPU.create({
  //...
})
const { Pixel } = plane.drawing

const drawn = scene.add({
  ...plane.drawing,
  pixelOf: (vertex) => {
    'use gpu'
    const color = material.pixelOf(vertex).color
    const world = vertex.world_position
    const face = std.normalize(std.cross(std.dpdx(world), std.dpdy(world)))
    const normal = std.select(std.neg(face), face, std.dot(face, cameras.towards(cameras.current.$, world)) >= 0)
    const surface = materials.glossy(std.div(color.xyz, std.max(color.w, 0.0001)), 0.35)
    return Pixel({ color: shading.shadeClear(surface, shading.pointAt(world, normal), color.w) })
  },
})
```

`material.pixelOf(vertex)` samples the UI in linear colors. The normal comes from the surface itself and is turned towards the eye, so both sides of the plane are lit. Functions marked with `'use gpu'` need `unplugin-typegpu` in your build.

## Customize the plane and hit mapping

Use the optional `createPlane()` callback to show the UI on something other than the default rectangle. It receives the UI `texture` view, the `material`, and the requested `world_width` and `world_height`. Return an object with a `transform` matrix as `plane`; additional resources are also returned by `UITypeGPU.create()`. uno does not draw a custom plane: add a drawing of your own to the scene, with `material.pixelOf` as its `pixelOf` and `pass.setBindGroup(material.bind_group)` in its `draw()`.

For custom interaction, return a `geometry` in `plane` and a `mapIntersection()` callback alongside it. The geometry is an indexed triangle geometry from `@typegpu/kit/geometry`. uno tests the pointer ray against its triangles, placed by `plane.transform`, and passes the closest hit to `mapIntersection()`, which returns UV coordinates as `{ x, y }`, or `null` to reject the hit. uno converts the returned UVs into UI layout coordinates, with `y = 0` at the bottom. Without this callback, uno maps hits against the default rectangle rather than raycasting the geometry.

For example, add this `createPlane` option to `UITypeGPU.create()` to make only the front (`+Z`) face of a box interactive:

```js
import { meshes } from '@typegpu/kit/geometry'
import { mat4 } from 'wgpu-matrix'

const { ui, plane } = await UITypeGPU.create({
  //...
  createPlane({ world_width, world_height }) {
    return {
      plane: {
        transform: mat4.identity(),
        geometry: meshes.box({ width: world_width, height: world_height, depth: 0.5 }),
      },
      mapIntersection(intersection) {
        return intersection.normal[2] > 0.5 ? intersection.uv : null
      },
    }
  },
})
```

The intersection holds the world `point`, the `local_point` and triangle `normal` in the geometry's own space, the `face_index` of the triangle, the interpolated `uv` of the geometry, and the `distance` from the ray's origin. Hits on the other faces return `null`; uno does not continue looking for an interactive face behind them.

The front face of `meshes.box()` has `V = 0` at the bottom, as uno's hit mapper expects, so its `uv` is returned as it is. The UI texture has its first row at the top: sample it with `1 - uv.y` when drawing this face.

`mapIntersection()` can also transform the UVs before returning them, allowing you to adapt interaction to a custom texture layout. It changes how hits are mapped to the UI; it does not change how the texture is rendered. uno reads the geometry once, when the UI is created, and reads `plane.transform` at each event.

## Cleanup

World-space UIs have resources owned by uno and resources managed by TypeGPU Kit. `ui.destroy()` releases the uno nodes, listeners, renderer allocations, and offscreen GPU texture. It does not remove the drawing from the pass description.

Before cleanup, stop this UI's draw calls and remove any event listeners added by your application. If a framework manages the layout, call its root's `unmount()` while the UI is still alive.

Destroy what `scene.add()` returned and the plane, then the UI:

```js
drawn.destroy()
plane.destroy()
ui.destroy()
```

uno releases the backing GPU texture in `ui.destroy()`; do not call `gpu_texture.destroy()` separately. If `createPlane()` or `createMaterial()` creates additional resources, release those too.

After the last overlay or world-space UI using the shared image and font atlases has been destroyed, dispose the resource store:

```js
resources.dispose()
```

This does not destroy the GPU device or canvas context. When the scene ends, release the UIs, the planes, `resources` and the TypeGPU Kit targets in its `destroy`; `hosted.destroy()` then releases the surface and the root. Keep them alive when removing only one UI panel.
